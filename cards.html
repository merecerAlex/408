1. 五大计算题型（80% 的题都在这）

题型 A：逻辑块号 → 物理块号（连续分配）

识别标志：题目给「起始块号 + 文件长度」，问「偏移 X 字节在第几块 / 物理地址是多少」。

流程：

  1. i = ⌊off / B⌋
  2. 判越界：i ≥ n（n 为文件块数）→ 访问失败
  3. b = start + i
  4. d = off mod B
  5. 物理地址 = b × B + d

例题：B = 1KB，start = 20，读偏移 3000 字节。

  • i = ⌊3000/1024⌋ = 2
  • b = 20 + 2 = 22
  • d = 3000 − 2048 = 952
  • 物理地址 = 22 × 1024 + 952

坑：

  • 逻辑块号从 0 起，不是从 1。
  • 只有连续分配能这么做。链接分配和索引分配不能直接 start + i。

题型 B：索引容量与最大文件长度

识别标志：题目给「块大小 + 地址项大小 + 几级索引」，问「能表示多大的文件 / 最大块号是多少」。

第一步永远是算 K：

K = 盘块大小 ÷ 每个盘块号所占字节数
  • 4KB 块 + 4B 地址 → K = 4096/4 = 1024 = 2^10
  • 1KB 块 + 4B 地址 → K = 256 ← 这是最常考的变体，死记 1024 必错

第二步套级数：

单级
K·1024 × 4KB = 4MB
二级
K²·2^20 × 4KB = 4GB
三级
K³·2^30 × 4KB = 4TB

二级索引的块号拆分（要会手算）：

  • k1 = ⌊i / K⌋（一级索引块内第几项）
  • k2 = i mod K（二级索引块内第几项）

代价：最坏读 3 次盘（一级索引块 + 二级索引块 + 数据块）。

题型 C：混合索引（UNIX 风格）★ 最高频

识别标志：题目给「索引结点含 10 个直接项、1 个一级间接、1 个二级间接、1 个三级间接」，问「最大文件长度」或「第 X 号逻辑块走哪条路、读几次盘」。

第一层：各类地址覆盖多少块

直接地址（10 项）
10·0 ~ 9
一级间接
K·10 ~ 10+K−1（10 ~ 1033）
二级间接
K²·1034 ~ 1034+K²−1
三级间接
K³·接着往下

第二层：最大文件长度

总块数 = 10 + K + K² + K³
最大长度 = 总块数 × 盘块大小

K = 1024、块 4KB 时：

10 + 2^10 + 2^20 + 2^30 块

≈ 4TB + 4GB + 4MB + 40KB

第三层：给一个逻辑块号 i，问走哪条路、读几次盘

i < 10
直接项·0
10 ≤ i < 10+K
一级间接，j = i − 10·1
落在二级区
j = i − (10+K)，拆 ⌊j/K⌋ 和 j mod K·2
落在三级区
按 j/K²、(j mod K²)/K、j mod K 拆三级·3

加上数据块本身，总访盘次数 = 上表 + 1。

坑：

  • 「访问第 i 块要几次访盘」必须把数据块算进去。题目若明说「索引块已在内存」，才只计数据块。
  • K 一定要按题给数据重算。

题型 D：位示图换算 ★ 最高频

识别标志：题目给「字长 n 位 / 每行 n 位」，问「盘块号 b 对应第几字第几位 / 第几行第几列」。

核心公式（全部从 0 起编号时）：

字号 i = ⌊b / n⌋
位号 j = b mod n
反算：b = i × n + j

若题目说行列从 1 起编号：

行号 = ⌊b/n⌋ + 1
列号 = (b mod n) + 1
反算：b = (行号−1) × n + (列号−1)

例题：字长 n = 16 位，共 256 个字（4096 个盘块）

  • (1) b = 100 → 字号 ⌊100/16⌋ = 6，位号 100 − 96 = 4；行号 7，列号 5
  • (2) 行 5 列 3 → 字号 4、位号 2 → b = 4×16 + 2 = 66

位示图占多少空间：

盘块数 ÷ 8 字节，或 盘块数 ÷ n 个字。

坑：

  1. 先看清「字长 n」和「行列从 0 还是从 1」——这两个条件错一个，答案全错。
  2. 字号/位号是位示图的定位，盘块号是磁盘的定位，两者只靠 b = i×n + j 换算，别混。
  3. 0 = 空闲、1 = 已分配（题设另有规定以题为准，一定要读题）。

题型 E：FAT 大小与 FAT 链

识别标志：题目给「磁盘大小 + 块大小」，问「FAT 有多少表项 / 占多大空间」。

流程：

  1. 盘块数 = 磁盘容量 ÷ 块大小
  2. FAT 表项数 = 盘块数（一个盘块对应一个表项）
  3. 每个表项 = 指针位数 + 1 位标志位
  4. FAT 总大小 = 盘块数 × (指针位数 + 1) ÷ 8 字节

FAT 的随机访问：链在内存里走，所以能随机访问第 i 块。但真正读那块数据仍要 1 次磁盘 I/O。

坑（三个高频混淆）：

FAT vs 位示图/成组链接
问一句「这张表记的是已用的还是空闲的」——FAT 记已用，另两个记空闲
FAT vs 索引分配
都是随机访问。区别：FAT 是全局一张表，索引分配是每个文件一块索引表
随机访问 ≠ 零 I/O
FAT 定位不需读盘，但取数据要读盘

题型 F：目录检索的 I/O 次数

识别标志：题目问「按绝对路径 /a/b/c.txt 访问文件，需要读几次磁盘」。

数法：

  1. 根目录一般常驻内存（这是常见题设简化，不是硬结论；题目若给了根目录位置或要求计根目录 I/O，必须计入）。
  2. 若目录项已拆成「文件名 + 索引结点号」：每级读 1 次目录块，名字匹配后再读 1 次索引结点。
  3. 若目录项就是完整 FCB（如 FAT 文件系统）：每级读入目录项本身即可。
  4. 文件已打开后再读写 → 不再检索目录，直接用内存中的打开文件表。

坑：题目常要求分开报「读目录几次 / 读索引结点几次」，必须按题设的数据结构拆开数，不能笼统说「几次」。

两条判定口诀：

  1. 能随机访问 ⇔ 不用「顺着链读盘」就能算出第 i 块的块号。
  2. 有外部碎片 ⇔ 要求连续空间 ⇔ 只有连续分配。

选择依据（简答题用）：

  • 频繁随机访问 + 大小基本固定（系统文件）→ 连续分配
  • 大小变化大 + 顺序读写（日志）→ 隐式链接
  • 要随机访问 + 要动态增长 + 小磁盘（FAT32）→ 显式链接
  • 通用大容量（Linux ext 系列）→ 混合索引

3. 成组链接法（唯一需要背流程的）

为什么有它：空闲块太多 → 空闲表太大；空闲链表又太长。所以「分组 + 链接」。

结构：

  • 空闲块分若干组（如每组 100 块）
  • 每组第一块存放组内其余空闲块的块号 + 指向下一组的指针
  • 各组从后向前链
  • 超级块保存「当前可分配组的块号 + 组内空闲块数」

分配（重点：取走组内最后一块）：

  1. 从当前组取一个空闲块 → 组内空闲块数 −1
  2. 当取到组内最后一块时：该块本身存着指向下一组的信息 → 先把下一组的块号信息读入超级块 → 再把这块分配出去
  3. 于是超级块切换到新的当前组
⚠️ 顺序不能反：漏了「先读下一组」这一步，链就断了。

回收（重点：满组时的顺序）：

  1. 把释放的盘块号直接登入超级块代表的当前组（只是内存操作，不写盘）→ 组内计数 +1
  2. 若当前组已满（如已 100 块）：先把超级块中的整组信息写入这块新释放的块 → 再把这个新块的块号放入超级块，使它成为新的当前组首块
⚠️ 顺序不能反：满组信息必须先写进新块，新块才能充当下一组的「组长」。若先当首块再写，会把组长自己的块号覆盖掉。

核心优点：只有超级块那一组常驻内存，其余按需调入 → 省内存 + 便于查找。

4. 概念辨析（选择题陷阱清单）

4.1 打开文件表三张结构

结构位置数量存什么
目录项 / FCB外存每文件一个文件名、属性、物理地址（真身）
系统打开文件表内存全系统一张FCB 副本、打开计数器、访问模式
进程打开文件表内存每进程一张fd → 系统表项指针、本进程读写位置

打开流程（口诀：先找文件、再登记、最后发号）：

  1. 按文件名逐级检索目录找到 FCB（目录检索只在此刻做一次）
  2. 查系统表：已有 → 计数 +1；没有 → 调入 FCB 新建表项，计数 = 1
  3. 在进程表分配空表项，填指针 + 读写位置
  4. 返回 fd（= 进程表表项的索引号）

关闭流程：删进程表项 → 系统表计数 −1 → 减为 0 才写回 FCB 并删系统表项

四个高频错点：

  1. fd 是局部唯一的，不是系统全局编号。不同进程打开同一文件，fd 可以不同。
  2. 同一进程两次打开同一文件 → 得到两个不同的 fd（产生两个进程表项）。
  3. 「打开」不读文件内容，只把 FCB 调入内存。读/写才真正传送数据。
  4. 关闭不等于立刻写回磁盘，要等计数归零。

4.2 硬链接 vs 软链接

本质
多个目录项指向同一个索引结点·新建一个只存路径名的 LINK 类型文件
计数
inode 里 count++，删除时 count−−·无计数
跨文件系统
❌ 不行·✅ 可以
对目录建链
❌ 不行（防成环）·✅ 可以
原文件删除后
✅ 内容仍可通过其他链接访问·❌ 链接还在但失效（悬空链接）
访问开销
与普通文件相同·多读一次链接文件
速记：硬链接 = 多名字共享同一 inode；软链接 = 一个只存路径的小文件。

4.3 逻辑结构三种

无结构（流式）
字符流、不划分记录、按字节计长、顺序访问·源程序 / 目标代码 / 可执行文件
顺序文件
按记录顺序存放，批量存取效率最高·批量快、单条慢、增删困难
索引文件
为变长记录建索引表，每记录一项·可随机、但索引表占空间
索引顺序文件
顺序文件分组，每组第一条建索引项·索引项每组一个，不是每记录一个
⚠️ 最常错：索引顺序文件的索引项是「每组一个」，索引文件才是「每记录一个」。

4.4 目录结构

单级
简单，可按名存取·不许重名、文件数受限、查找慢
两级
不同用户可重名、检索快、有访问控制·不灵活、不能共享
树形
分类管理、不同目录可重名、可设权限·不便共享（一个文件只能一个父目录）
无环图
可共享（多目录项指向同一文件）·需共享计数器，删到 0 才真删；管理复杂

4.5 文件保护三法

口令
内容机密·口令存系统内部，不够安全
加密
内容机密·密钥管理麻烦
访问控制（ACL）
操作权限·表可能很大
口诀：口令/加密保护「内容机密」，访问控制保护「操作权限」。

4.6 文件系统分层（自下而上，必背顺序）

I/O 控制层  →  基本文件系统层  →  文件组织模块层  →  逻辑文件系统层
I/O 控制层
设备驱动 + 中断处理，与硬件交互
基本文件系统层
向驱动发通用命令，读写物理块（不关心内容）
文件组织模块层
逻辑块 → 物理块映射、空闲空间管理
逻辑文件系统层
元数据（FCB/目录）、按名存取、权限检查、用户接口
记忆：逻辑层管名字与权限，组织层管逻辑块到物理块，基本层管物理块读写，I/O 层管硬件。

4.7 磁盘布局（按序）

引导块 → 超级块 → 目录结构 → FCB（索引结点）区 → 数据区
  • 引导块：分区第一个块，不属于文件系统本身
  • 超级块：分区大小、空闲块数与指针、空闲 FCB 数与指针；挂载时才读入内存

5. 空闲空间管理四种方法

方法原理适用缺点
空闲表每个空闲区一项：序号 + 首块号 + 块数连续分配空闲区多时表很长
空闲链表（盘块链）空闲块逐块拉链简单逐个摘取，工作量大
空闲链表（盘区链）以「连续空闲区」为单位拉链较高效回收需合并相邻盘区
位示图1 bit / 块，0 空闲 1 已用中小型 FS顺序扫描找空闲位
成组链接分组 + 链 + 超级块超大 FS（UNIX）结构复杂

选型口诀：小块数看位示图，大容量看成组链接，连续分配配空闲表。

6. 一次完整寻址（综合题模板）

题目：「读文件偏移 off 处的内容，共需几次访盘？」

① i = ⌊off / B⌋，d = off mod B
② 由目录（或其缓存）找到该文件的索引结点 FCB
③ 按 i 落在直接/一级/二级/三级区，选路径得物理块号 b
    额外读盘：直接 0 次、一级 1 次、二级 2 次、三级 3 次
④ 按 b 读出整个盘块（1 次磁盘访问），取出 [d, d+长度) 的数据
⑤ 若跨多个盘块，对 i, i+1, … 重复 ③④
⚠️ 「访问第 i 块几次访盘」= 索引块读取次数 + 数据块 1 次。题设若说「索引块已在内存」，才只计数据块。
